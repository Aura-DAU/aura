## Course Description

The Software Engineering course introduces the basic principles, practices, tools, and techniques required to engineer large complex software systems. The course is project-intensive, where students learn by example and practice. The main objective is to understand and learn how complexity and change are engineered during large software development. The course focuses on the methodologies (processes), techniques (methods), and tools that can be used to successfully design and validate large software. Wherever relevant, various technologies (e.g., DevOps, CASE) will be used to represent various aspects of software development.

The contents covered include: (1) Software Requirements Modeling and Specifications, (2) Software Architecture and Design Patterns, Software Development Methodologies, (3) Software Measurement and Metrics, (4) Computer Aided Software Engineering and Tool Support (DevOps, Automation), (5) Software Quality Standards and Quality Assurance, (6) Applications of ML and AI in analyzing software products.

**Preamble:** Writing programs to fulfil some academic requirements for an academic degree is a radically different exercise compared to how state-of-art software is developed in industry. ## Evaluation / Grading Scheme

| Component | Weightage |
|---|---|
| First In-Semester Exam | 10% |
| Second In-Semester Exam | 10% |
| End-Semester Exam | 30% |
| Course Project Work | 40% |
| Lab, Assignments (or Presentations), Experiments | 10% |
| **Total** | **100%** |

**Marking Scheme for Projects:**
1. The group mark is everybody's mark, i.e., individual assessment of 25% and group assessment of 15% (within the 40% Course Project Work component).
2. Everybody reports what they personally did, and separate marks are given to those components by the instructor. This can be done using either a dossier of rough work or a division of labour report produced by team members.
3. Other group members report (confidentially or openly) the relative contributions of other group members to allow for an adjustment of the final grade.
4. Pop quizzes in class to ensure students know the intimate details of the project.
5. Cross-validating with the results of individual work (possibly reducing the weight of group work for students who perform poorly on exams or individual assignments).
